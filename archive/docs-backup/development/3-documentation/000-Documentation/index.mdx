## Architecture

The Documentation Engine is a hybrid system combining static site generation with dynamic, permission-aware navigation. It transforms a flat directory of MDX files into a structured knowledge base, enforcing role-based access control at the routing level while providing rich content rendering capabilities.

### Purpose

The system operates as a pipeline that ingests source files, filters them based on user warrants, and renders the resulting navigation tree.

### Routing

The engine uses a bespoke routing utility to generate the site structure at runtime. It maps the physical file system to a logical navigation tree.

```plaintext
📂 Section                            Sidebar UI
└── 📂 001-Group                      ▾ Intro
    ├── 001-Leaf/
	│	├── index.mdx         ==>      • Leaf
	│   └── attachment.pdf
    │
	└── 002-Legacy.mdx                 • Legacy
```

The `Tree` component acts as a recursive factory that dynamically maps structural layers and evaluates context dependencies to render the navigation interface.

===[Branches]

Rendered as `SidebarGroup` components, branches represent collapsible folder containers.

* **Context Menus**: Branches provide administrative actions to add new pages, download the entire group (as a preserved ZIP, merged PDF, or visual snapshot), rename the group, or delete the section.
* **Drag and Drop**: Branch drop-zones accept both files and other folders, recalculating the `000-prefix` ordering architecture sequentially upon drop.

===

===[Leaves]

Rendered as `SidebarMenuItem` components, leaves represent individual markdown documents.

* **Context Menus**: Leaves include comprehensive file operations, such as renaming, duplicating, downloading, and deleting.
* **Attachments Management**: A dedicated "Files" submenu allows authors to upload local assets, rename attachments, duplicate them, or execute LLM content synthesis directly against them.

===

===[Table of Contents]

Active leaves automatically mount a `Toc` component that generates a dynamic scroll-spy navigation list.

* **Tracking**: It utilizes a `MutationObserver` and event listeners (`scroll`, `resize`) to scan the active viewport for `<h2>` headings.
* **Visibility**: Headings are mapped to their respective IDs and dynamically highlighted in the sidebar as the user reads through the document.

===

===[Drag and Drop]

Both branches and leaves utilize a unified drag-and-drop state machine (`ReorderDropState`).

* **Geometric Resolution**: Hover coordinates determine if a dropped item should be placed `before` or `after` a target node.
* **Cross-Layer Support**: The `uploadAsLeaf` and `mvLeaf` utilities safely transition nodes between entirely different branch directories natively.

===

## Blocks

The MDX engine is augmented with custom components and global styles to support technical documentation requirements.

===[Accordions]

Consolidates lengthy content into collapsible sections for progressive disclosure. Uses the \=\=\= syntax.

===

===[Tabs]

Groups distinct sections into a compact, switchable interface. Uses the ||| syntax.

===

===[Steps]

Renders sequential instructions with visual tracking lines. Uses the ^^^ syntax.

===

===[Asides]

Highlights contextual information using categorized colored blockquotes (Note, Tip, Caution, Danger). Uses the ::: syntax.

===

===[Flowcharts]

Visual layout engine for diagrams. Utilizes **React Flow** and **Dagre** to automatically position nodes defined via YAML frontmatter.

* **Auto-Layout**: Dagre automatically calculates coordinates based on graph topology (TB or LR).
* **Static Positioning**: Explicit coordinates provided in the frontmatter override Dagre's auto-layout.
* **Proximity Connections**: Handles can dynamically assign themselves based on the geometric relationship between nodes rather than strict directional anchoring.

===

===[Code]

Integrates **CodeMirror** for syntax highlighting and raw editing.

* **Capabilities**: Supports real-time theme swapping, line boundary selections, and robust clipboard interception to automatically convert pasted HTML into valid markdown.
* **Styling**: Inline code blocks use `bg-primary-4` and `text-primary-12` with a rounded border radius to cleanly stand out from regular prose.

===

===[Math]

Renders LaTeX expressions securely via **KaTeX**.

* **Inline vs Block**: Supports both inline (`\$`) and block (`\$\$`) display modes.
* **Visual Editor**: Managed through a dedicated Radix UI popover editor that allows authors to type and preview formulas in real-time, completely bypassing brittle remark AST plugins.

===

===[Tables]

Renders as a native HTML `contenteditable` grid to support inline markdown formatting, bypassing deep nesting limitations in standard MDX editors.

* **Toolkit**: Features a spreadsheet-like cell manipulation toolkit allowing authors to add, delete, and merge rows or columns intuitively.
* **Responsive**: Markdown tables use `border-collapse: separate` with rounded corners, dynamically wrapping in an overflow container for mobile viewports.

===

===[Images]

Provides dialog controls for device uploads and remote URL parsing.

* **Interception**: Intercepts `dragover` and `paste` clipboard events to instantly transform dropped files or remote `<img>` tags into inline markdown syntax.
* **Context Actions**: Injects a floating hover-menu over active editor image nodes to quickly access dimension settings, alt-text parameters, or deletion commands.

===

===[TsDocs]

Queries the content collection to dynamically list and link to auto-generated TypeScript definition pages. The output can be scoped to specific directories using the `filter` prop.

===

## Actions

The backend operations power the documentation engine, handling file system modifications, access control, and structural integrity.

===[parse.ts]

The `parse` utility handles string manipulations, path resolution, and MDX compilation.

		</tr>

		<tr>
			<td><code>path</code></td>
			<td>Normalizes routing paths based on semantic entity types (<code>file</code>, <code>folder</code>, <code>asset</code>, <code>store</code>). Validates paths rigidly to ensure execution stays strictly within the documentation directory.</td>
		</tr>
		<tr>
			<td><code>src</code></td>

		<tr>

		</tr>
		<tr>
			<td><code>mdx</code></td>
